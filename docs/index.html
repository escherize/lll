Self-hosted issue tracking

Terminal first.Browser second.

Teams, ENG-123 identifiers, states, priorities, projects, labels and markdown comments. Driven from the command line, with a live board for the glance. One binary, with the database compiled into it.

Install
$ mkdir -p ~/bin && curl -LsSf -o ~/bin/lll \
    https://github.com/escherize/lll/releases/latest/download/lll-darwin-arm64 \
    && chmod +x ~/bin/lll

$ lll --version
lll 0.1.0
darwin-arm64 linux-amd64 linux-arm64

From nothing to a board

Three commands, in this order.

01

Point at a server

Holding the server's admin credentials, one command makes your account and logs into it, writing the url, the token, your name, and, when the server has exactly one team, that too.

lll login
$ lll login --url https://tracker.example.com --email you@example.com \
    --create --password <pick one> \
    --admin-email <admin> --admin-password <admin pw>
created member you <you@example.com>
url = "https://tracker.example.com" in ~/.config/lll/lll.toml
logged in as you
token saved to ~/.config/lll/lll.toml
me = "you" in ~/.config/lll/lll.toml
team = "ENG" in ~/.config/lll/lll.toml (the server's only team)
ready: lll issue create "a title"
02

Work

Every command takes --help; every read takes --json. Issue ids resolve from the current git branch, so eng-1-fix-login means ENG-1 without your typing it.

lll issue
$ lll issue create "Fix the login flow" --priority 1 --label bug
Created ENG-1: Fix the login flow

$ lll issue list
ENG-1   in-progress   Fix the login flow    just now
ENG-2   todo          Board rail spacing    2h ago
ENG-3   done          Portless url          yesterday
03

Attach the repo, once

lll attach writes team = "ENG" into a committed .lll.toml. Every later clone and every git worktree arrives configured: nothing to run, nothing to paste.

lll attach
$ lll attach
the server has one team, ENG — attaching to it
team = "ENG" in /work/api/.lll.toml
commit .lll.toml — every clone and worktree of this repo is attached from then on

What you get

A tracker that runs where you run. PocketBase is compiled into the binary and served in-process, so a deployment is one file and one volume. No database to provision, no broker, no second service to keep alive.

A live board

Server-rendered, with drag-and-drop between states. Changes from the CLI, another browser, or the board itself land everywhere over one SSE connection, with no reload.

Search that is a URL

/search?q=… queries the database rather than the rendered page, so the query is shareable and curl gets the same answer the browser does.

Config that layers

Environment beats the repo file beats your home file, and every key resolves on its own. lll config --list names every winner and the file it came from.

Branch-aware

lll issue start creates the branch; later commands infer the id back from it. lll issue pr opens the pull request already titled.

For the agents

The CLI is the API. Reads take --json. Changes arrive as a newline-delimited event stream you can pipe straight into something. An agent gets its own member record and a long-lived token, so authorship is a fact the server knows rather than a convention everyone remembers.

Streams and tokens
$ lll watch --state in-review --json | jq -r '.record.title'
Fix the login flow
Board rail spacing

$ lll token create deploy-bot
token for deploy-bot, shown once:
  eyJhbGciOi…
set it as LLL_TOKEN in the agent's environment

Run it

lll up starts PocketBase and the board together, picks free ports when the ones it wants are taken, and prints the credentials it just upserted. Locally that is the whole setup; on a host it is the same command with secrets in the environment and a volume for the database.

lll up
$ lll up
lll    0.1.0
admin  http://127.0.0.1:8090/_/  admin@local.dev / admin-local-123
team   ENG
me     bryan
board  http://127.0.0.1:8100
