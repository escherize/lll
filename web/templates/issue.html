Rendered ONCE per page load and deliberately outside #issue-detail: the catalogue is 241 candidates, and inside the morph boundary every issue event would re-send all of them to every open copy of this page. Being position:fixed, its place in the DOM costs nothing — the trigger measures itself and drops the panel under itself, exactly as .card-pop escapes the column's clipping. Filtering is the board's card-search idiom, not a new one: each candidate carries its search words in data-n and its own data-show, so typing narrows the grid with no client-side loop (Datastar v1 has none) and no round trip. One data-on:click on the grid delegates for all of them and reads the glyph off the button's own text, which is what holds the rendered markup to ~138 bytes a cell (33KB for the grid). The picker's own chrome obeys the Drawn Icon Rule — sprite magnifier, sprite close, sprite remove. Only the candidates are glyphs, which is the one exception DESIGN.md carves out (the author's per-issue marker). "Remove emoji" is the way back to none.
